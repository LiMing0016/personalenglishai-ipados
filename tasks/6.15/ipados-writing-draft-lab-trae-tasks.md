## A1：实现本地写作草稿存储

标签：中等 / feature迭代 / 前端

### Prompt

请在当前 iPadOS SwiftUI 项目的 Writing 模块中实现本地写作草稿存储。这个需求是能力测试题，不是真实产品需求；不要接后端，也不要改 Auth、Assistant 或 Profile 模块。

当前项目已有 `DraftStore` 协议和 `InMemoryDraftStore` 占位，请补齐一个可用于 App 的本地草稿存储，并让写作页能加载和保存草稿。

### 要求

- 新增草稿模型，至少包含 `id`、`title`、`content`、`mode`、`prompt`、`updatedAt`、`wordCount`。
- 新增本地实现，例如 `FileDraftStore` 或等价实现，数据保存到 App sandbox 的 Application Support 目录。
- 保留 `DraftStore` 协议边界；View 不直接读写文件。
- `WritingRootView` 根据 `draftID` 加载草稿内容。
- 编辑作文、切换写作模式、修改考试题目后自动保存。
- 新建草稿时生成新的 id，并在列表中可见。
- 空作文的标题使用“未命名草稿”，非空作文标题取正文第一行前 20 个字符。

### 验收标准

- 退出并重新进入写作页后，草稿内容仍然存在。
- 新建草稿不会覆盖已有草稿。
- `WritingHistoryView` 不再只显示固定 sample 数据。
- 本地存储失败时页面不崩溃，并显示可理解的错误提示。
- iPad 模拟器构建通过。

## A2：补齐草稿列表交互和空状态

标签：中等 / feature迭代 / 前端

### Prompt

请在 A1 基础上完善 Writing 草稿列表体验。仍然只做本地草稿实验室，不接真实后端。

### 要求

- `WritingHistoryView` 展示真实本地草稿列表，按 `updatedAt` 倒序排列。
- 每条草稿展示标题、两行预览、写作模式、字数、最后更新时间。
- 支持删除草稿，删除当前选中草稿后自动选中下一条；没有草稿时右侧显示空状态。
- 支持搜索草稿，搜索范围包含标题、正文预览和考试题目。
- 新建按钮创建空草稿并立即选中。
- 列表加载、空状态、错误状态要有明确 UI。

### 验收标准

- 创建 3 个草稿后，最近编辑的排在最上面。
- 搜索关键词时列表正确过滤，清空搜索后恢复完整列表。
- 删除草稿后不会留下失效的 `selectedDraftID`。
- 没有草稿时，新建按钮仍可用。
- VoiceOver 至少能读出草稿标题、模式和字数。

## B1：增加草稿恢复和冲突保护

标签：困难 / 工程化 / 前端

### Prompt

请在 A1/A2 基础上补齐草稿恢复和冲突保护。这个题目用于测试工程完整性，不需要做真实多设备同步。

### 要求

- 自动保存使用 debounce，避免每次键入都写文件。
- 如果保存失败，保留内存中的最新内容，并允许用户重试保存。
- App 再次打开同一个草稿时，如果本地文件损坏或 JSON 解析失败，不要崩溃。
- 损坏草稿要在列表中以“无法读取的草稿”显示，并提供删除入口。
- 写入文件时使用临时文件加原子替换，避免半写入文件。
- 对 `wordCount` 做轻量统计：英文按单词计数，中文按非空白字符计数。

### 验收标准

- 快速连续输入时，不会触发大量同步写入。
- 手工放入损坏 JSON 草稿后，App 仍能打开 Writing 模块。
- 损坏草稿可以被删除。
- 保存失败后，用户继续编辑不会丢失屏幕上的内容。
- 原子写入逻辑有单元测试或可检查的封装。
