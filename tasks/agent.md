# 出题 Agent

这个目录用于保存给 Trae 模型的需求题。出题时只参考两类信息：

- 用户当前提出的需求
- `docs/agent.md` 以及 `docs/` 目录下和当前需求相关的文档

出题目标：把当前需求整理成 Trae 可以直接执行的题目，不写长背景，不扩展无关范围。

## 分组规则

每次出题分成两组：

- A 组：基础题，要求明确，主要验证模型能否按现有项目规则完成需求。
- B 组：进阶题，在 A 组基础上增加边界情况、工程完整性或产品细节。

每组可以包含 1 道或多道题。题目要小而清楚，避免一题塞进多个阶段。

## 每道题目格式

```md
## A1 / B1：<题目标题>

标签：<难度> / <题目类型> / <实现范围>

### Prompt

<给 Trae 的完整需求 prompt>

### 要求

- ...
- ...
- ...

### 验收标准

- ...
- ...
- ...
```

## 标签规则

### 难度

- 简单：改动范围小，主要是补页面、补字段、补文档或轻量接口。
- 中等：需要跨多个文件，涉及前后端之一的完整小功能。
- 困难：需要全栈联动、数据流闭环、测试和文档同步。

### 题目类型

- `01代码`：偏代码基础实现，例如接口、组件、类型、测试、修 bug。
- `feature迭代`：偏产品功能迭代，例如新增页面流程、交互、业务能力。
- `工程化`：偏工程质量，例如目录结构、脚本、文档、测试、配置、可维护性。

### 实现范围

- `前端`：主要改 React、页面、样式、交互、前端类型。
- `后端`：主要改 Go API、数据库、迁移、storage、接口测试。
- `全栈`：同时涉及前端、后端、数据流或端到端验收。

## 出题要求

- Prompt 要能直接复制给 Trae。
- 要求必须具体，不写“优化一下”“完善一下”这种模糊表达。
- 验收标准必须可检查，可以是页面行为、接口响应、测试命令或文档结果。
- 每题必须标记难度、题目类型和实现范围。
- 不要求 Trae 处理当前需求之外的长期规划。
- 默认用中文出题。
